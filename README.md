# 小禹 · 村镇水处理站智能运维平台

村镇污水站通常只有一两个人值守：工艺靠经验、异常靠电话、台账靠纸。小禹把这三件事收进一套原生软件——电脑上看全站，手机上接单与巡检，装完即用，不需要服务器。

![运行总览](docs/screenshots/native/page-dashboard.png)

**一座站，两块屏**

- **Windows 桌面端**：C# / .NET 8 / WPF 原生程序，业务与数据都在本机，不依赖浏览器或服务器。
- **安卓 App**：Java + SQLite，内置本机引擎，不连电脑也能独立运行；也可以连平台服务看同一份数据。
- **Web 版**：仓库保留源码，供浏览器访问与二次开发。

### 它管什么

- **一座站的完整工艺链**：进水调节池 → 格栅池 → 序批预氧化池 → 配水槽 1 → BAF → PAC → PAM → 配水槽 2 → 自养脱氮池 → 清水池 → 废水箱，液位、pH、DO、流量、压差、加药、反冲洗每 3 秒刷新。
- **异常先于人来**：阈值 + 持续时长 + 迟滞 + 升级的四级告警；确认、恢复、关闭全程留痕，附带 MTTA / MTTR。
- **处置闭环**：告警或巡检异常可一键转工单，派发 → 接单 → 处理 → 验收 → 关闭，责任人和时间都记录在案。
- **数据有出处**：在线仪表与人工化验分开展示，没有的仪表明确标「未布点」，不拿估算值冒充实测。
- **权限到站点**：6 类角色 + 站点数据范围双重校验，越界由业务层拒绝，而不是只在界面上藏按钮。

## 一、快速开始

### 方式一：Windows 桌面版（推荐）

1. 下载最新已发布的 `Xiaoyu-Setup-2.0.21.exe`，双击安装（可选择安装目录、创建桌面与开始菜单快捷方式）。
2. 从桌面「小禹」启动。原生窗口，不需要浏览器、不需要 Node.js。
3. 用演示账号登录；首次启动会把内置种子数据复制到 `%LOCALAPPDATA%\ZhifuWater\data\db.json`，之后的数据读写都在本机。

> 卸载程序会移除安装目录与快捷方式，但**不会删除** `%LOCALAPPDATA%\ZhifuWater` 下的数据；需要清空时手动删除该目录即可。

### 方式二：安卓 App（原生、可离线）

1. 下载最新已发布的 `zhifu-water-mobile.apk`（Android 2.0.21），在手机上允许「安装未知来源应用」后安装。
2. 打开 App，点「**直接进入（本机演示）**」——不需要电脑、不需要填服务器地址。
   数据存在手机本地 SQLite；本机引擎在后台每 5 秒推进 site-1 的模拟遥测与告警（界面随之静默刷新）。告警确认、工单流转和巡检提交会持久化在手机上，重启 App 后仍保留。离线演示与电脑端数据彼此独立，也不会连接现场 PLC。
3. 如果想看电脑上的平台数据：先在电脑上用 `node server/index.js --host 0.0.0.0` 启动服务，再在登录页展开「连接服务器」，填 `http://电脑IP:8765`，用同一套账号登录。服务默认只监听本机地址，局域网连接时需显式开启监听。

> App 是**完全原生**的 Java 实现（Activity + 框架 View + SQLite，无 WebView、无 Gradle、无 androidx、无第三方库）。本机模式下数据仅存在手机上，与电脑端互不影响。设备控制与参数修改只留在桌面端：它们需要联锁校验与二次确认，手机屏幕不适合承载。

### 方式三：Web 版（开发/演示）

```bash
node server/index.js
```

浏览器打开 **http://127.0.0.1:8765**（需 Node.js 18+，无其他依赖）。Windows 也可双击 `启动平台.bat`。

服务器默认只允许本机访问。需要让同一局域网的手机连接时，使用 `node server/index.js --host 0.0.0.0`，并在受控网络中运行。

Web 端与桌面端同为 2.0.21：品牌、浅色水务蓝界面、数据模型一致。

## 三、数据边界（重要）

平台严格遵守方案的「不伪造数据」原则：

1. **有在线仪表的**：进水调节池液位、提升泵状态/运行小时、进水流量（选配）、BAF 与自养脱氮池 pH/DO、曝气风机电流、反冲洗状态、PAC/PAM 药箱液位与投加量、清水池/废水箱液位、功率与电能。桌面端由内置 C# 模拟引擎、安卓端由本机引擎按工艺机理每 5 秒生成并写入本地库。
2. **图纸未确认的表计**：进水流量计、TN/COD/氨氮/总磷/SS 在线分析仪一律标 `provenance: optional` 或「未布点」，界面不显示实时值。
3. **人工化验**：COD、氨氮、总氮、总磷、SS 由「水质化验」录入，状态为「待复核 / 已复核 / 已驳回」，并标注方法与取样点；运行总览引用时显示 `人工化验 · 时间`。
4. **模拟引擎**：桌面端 `native/ZhifuWater.Core`（C#）与安卓端 `LocalEngine` 都是确定性工艺模型，**不连接现场 PLC**。所有设备控制只作用于模拟引擎，命令的联锁、回执、超时、审计均为真实业务逻辑。
5. **试运行承诺**：方案第 15 章的「连续试运行 ≥ 30 天」「数据接入成功率 ≥ 99%」需现场部署后验证，本演示版不承诺。

### 数据口径

所有页面读的是同一份数据（一个 `CoreServices` 实例、一份 `db.json`、每 5 秒推进一次、界面每 3 秒刷新）。下面这些名字在不同页面出现，含义是固定的：

| 数字 | 定义 | 出现位置 |
| --- | --- | --- |
| 今日处理水量 | 当日 0 点到现在，进水流量积分 | 运行总览、报表 |
| 累计处理水量 | 所选统计周期内的进水流量积分 | 运行分析 |
| 出水 COD | 最近一条「总出水」人工化验值（不是在线仪表） | 运行总览、水质化验、报表 |
| 去除率 | (进水 − 出水) ÷ 进水，用同一天的人工化验值 | 水质化验、运行分析 |
| 未关闭告警 | 状态为「未处理 + 已确认未恢复」的条数 | 运行总览、侧栏角标 |
| 待确认告警 | 只看未确认（active） | 告警管理 |
| 已确认未恢复 | 已确认但参数还没回到安全区 | 告警管理 |
| 今日已恢复 | 今日 0 点以来恢复到正常区的条数 | 告警管理 |
| 本期告警（近 N 天） | 统计周期内新产生的全部告警，含已恢复、已关闭 | 运行分析 |
| 待处理工单 | 未闭环的工单（待接单 → 待验收） | 运行总览、侧栏角标 |
| 新增工单 | 统计周期内新建的工单 | 运行分析、报表 |
| 运行设备 | 通讯正常的设备台数（不等于正在运行） | 运行总览 |
| 需关注设备 | 健康分 < 90 或离线的设备 | 设备台账、运行总览 |
| 点位在线率 | 质量正常（good）的点位数 ÷ 总点位数 | 运行总览、运行分析 |
| MTTA / MTTR | 从触发到确认 / 从触发到恢复的平均分钟数 | 告警管理 |
| 吨水电耗、吨水成本 | 当日电耗、当日（电费 + 药费）÷ 当日水量 | 运行总览、运行分析 |
| 报表里的数字 | 生成那一刻的快照，之后不再随时间变化 | 报表中心 |

**报表是快照，其他页面是实时视图**：报表要留档，所以生成后数字固定；想看当前值请回到对应页面。
6. **演示数据的量级说明（避免误读）**：装置处理能力 100 L/h（0.1 m³/h），按连续运行折算约 **2.4 m³/日**；遥测保留 **30 天**（最近 24 小时 5 分钟粒度，更早为 1 小时粒度）。
   - 药剂投加设定：PAC **0.06 L/h**、PAM **0.02 L/h**，折算吨水药耗约 **0.60 / 0.20 L/m³**；
   - 吨水电耗约 **13.8 kWh/m³**——这是小型实验装置按 0.1 m³/h 折算的真实量级（搅拌器、风机、加药泵长期运行，水量却很小），**明显高于常规市政污水厂 0.3–0.5 kWh/m³**，不代表工艺落后；
   - 吨水成本约 **12.7 元/m³**：电费按 0.65 元/kWh、PAC 2.2 元/L、PAM 12 元/L 的**演示单价**估算，仅用于趋势对比，不作为结算依据。

## 四、技术选型与方案的差异

方案第 10 章建议 Vue3 + TypeScript + ECharts + Spring Boot + MySQL/PostgreSQL + MQTT + Docker。本机环境无法安装这些依赖，且目标是「双击即用」，因此实现如下：

| 方案建议 | 本实现 | 原因与影响 |
| --- | --- | --- |
| Spring Boot 后端 | **C# .NET 8 业务层**（`native/ZhifuWater.Core`）；Web 版另用 Node 标准库 | 桌面端单进程原生运行，不需要额外服务；接口与数据模型仍按方案第 8 章组织 |
| MySQL/PostgreSQL | JSON 文件存储（桌面 `%LOCALAPPDATA%\ZhifuWater\data\db.json`；安卓 SQLite） | 单站演示足够；数据访问已隔离在 Store/LocalDb，替换数据库不影响业务 |
| Vue3 + ECharts | **WPF XAML 原生控件 + 自绘图表**；Web 版为原生 ES Module + 内联 SVG | 无浏览器、无 CDN、无构建步骤 |
| MQTT | 内置 C# / Java 模拟引擎，5 秒节拍 | 保留「网关 → 平台 → 界面」链路；接真实 MQTT/Modbus 时替换引擎即可 |
| Docker | 桌面安装包 / APK 直接分发 | 单文件部署更简单 |
| Java 权限框架 | `Auth` + 角色权限表（C#/Node 各一份，规则一致） | 功能权限 + 站点范围双重校验，越界直接拒绝 |

## 七、已知限制

1. 模拟引擎按 5 秒节拍生成数据，历史保留 30 天（最近 24 小时按 5 分钟落桶，更早按 1 小时落桶）；生产需改为实时库 + 时序库。
2. 文件存储（桌面 JSON / 安卓 SQLite）在单机单进程下可靠；多实例并发写需改用数据库。
3. 报表 CSV 为 UTF-8 BOM 编码，适合 Excel；正式报表模板（Word/PDF）需按方案第 11 章扩展。
4. 通知通道为「模拟发送」（站内通知必达，短信/微信/邮件记录发送结果），接入真实通道需配置供应商密钥。
5. 桌面端为自包含单文件程序，启动时需解压运行时，首次打开约 2–4 秒。桌面端会从 GitHub Releases 自动检查更新：发现新版本后可一键下载、校验、静默安装并重启，也可在用户菜单里手动检查。
6. 安卓端本机模式的数据与告警由手机本地生成，与电脑端互不同步；需要同一份数据时改连服务器。当前构建未在真机上做过安装与触控验收（本机无安卓设备/模拟器），已完成编译、签名、包信息与逻辑自测。
7. 本平台是方案 V2.2 的**演示实现**，用于评审、演示与后续开发基线，不替代现场 PLC 安全联锁。
