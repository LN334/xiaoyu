# 小禹现场数据接入接口

## 用途和边界

该接口让现有边缘网关把 PLC/仪表可读数据以只读遥测方式送入小禹。网关负责把现场协议转换为下述 HTTP JSON 格式；云端据点位编码校验站点归属，更新最新值、告警规则输入、WebSocket 实时数据和站点总览。接口不接受设备控制命令，也不修改 PLC 参数。

目前仓库没有具体试点站的 PLC 型号、寄存器地址和网络资料。因此接口定义的是平台接入契约；真实网关驱动仍需按现场设备编写和逐点验收。没有网关发送数据之前，页面不能显示为现场已接入。

## 启用真实网关模式

为每个网关准备唯一 ID 和至少 32 位随机 Token。将其配置在服务进程环境变量 `XIAOYU_GATEWAYS_JSON` 中，按 `gatewayId → siteId + token` 绑定。Token 不要写入仓库、前端、演示账号或日志。

PowerShell 示例：

```powershell
$env:XIAOYU_GATEWAYS_JSON = '[{"id":"edge-site-1","siteId":"site-1","token":"replace-with-at-least-32-random-characters"}]'
node server/index.js --data data-site-1 --no-sim
```

`--no-sim` 会停止模拟遥测，关闭控制动作和参数写入 API，并恢复 `data-site-1/telemetry.jsonl` 中最近 30 天的网关历史。请给现场试点使用独立数据目录；不要把真实遥测写入开发演示库。

服务本身不提供 TLS 终止。正式网络应通过 HTTPS 反向代理或受控 VPN 暴露接口；不要把未加密的 HTTP 端口直接开放到公网。离线缓冲补传数据允许最早 30 天；未来时间最多允许偏差 5 分钟。

## HTTP 契约

`POST /api/ingest/v1/telemetry`

请求头：

```text
Content-Type: application/json
X-Xiaoyu-Gateway: edge-site-1
Authorization: Bearer <gateway-token>
```

请求体：

```json
{
  "eventId": "edge-site-1-20261113T021500Z-000001",
  "observedAt": "2026-11-13T02:15:00.000Z",
  "readings": [
    { "code": "RAW.LVL", "value": 42.6, "quality": "good" },
    { "code": "RAW.PUMP.RUN", "value": 1, "quality": "good" },
    { "code": "BAF.DO", "value": 2.85, "quality": "good" }
  ]
}
```

`eventId` 是网关生成的唯一批次编号；运行期间重复批次会幂等返回。`observedAt` 使用 UTC ISO 8601，可在单条 reading 上用 `observedAt` 覆盖。`code` 必须已配置在绑定站点的 `points` 清单中。值可为有限数字或不超过 80 个字符的状态字符串；`quality` 取 `good`、`uncertain`、`bad` 或 `stale`。仅 `good` 数据参与工艺阈值规则，其他质量状态仍会显示并进入实时数据流。

成功响应示例：

```json
{
  "ok": true,
  "data": {
    "gatewayId": "edge-site-1",
    "siteId": "site-1",
    "eventId": "edge-site-1-20261113T021500Z-000001",
    "duplicate": false,
    "accepted": 3,
    "receivedAt": "2026-11-13T02:15:00.120Z"
  }
}
```

## 现场批次快速联调

仓库提供 `scripts/send-gateway-batch.mjs`，用于把网关驱动已经读取并完成寄存器映射的 JSON 推到平台。它只负责 HTTPS/HTTP 上送，不连接 PLC，也不生成演示数值。先将一批经现场表计核对的数据保存为 UTF-8 JSON 文件，然后在调试电脑设置：

```powershell
$env:XIAOYU_URL = 'https://你的平台域名'
$env:XIAOYU_GATEWAY_ID = '现场网关编号'
$env:XIAOYU_GATEWAY_TOKEN = '至少32位随机密钥'
node scripts/send-gateway-batch.mjs .\现场批次.json
```

Token 只通过环境变量传递，不要写入批次文件、脚本或仓库。响应中 `accepted` 应等于批次点位数；`latestUpdated` 可能较少，因为迟到的补传数据只入历史，不覆盖较新的当前值。收到 `UNKNOWN_POINT` 时先核对平台点位清单；收到成功响应后，再核对站点最近数据时间、来源和单位。请不要把示例/虚构数值写入正式站点库。

常见错误包括：网关身份无效（401）、点位未配置（422）、重复点位/错误时间/错误质量（400）、未配置真实网关（503）。请求体最多 2 MB，每批最多 1000 个点位，且同批次每个点位只出现一次。

## 数据处理和持久化

网关遥测即时更新最新值、触发数据质量标记、广播到授权站点用户的 WebSocket，并交给现有告警规则引擎判断。历史记录按每点位 5 分钟桶采样，追加写入 `<data目录>/telemetry.jsonl`；重启后读取并保留最近 30 天。此本地 JSONL 方案用于先跑通有限规模试点；站点/点位数量和采样负载扩大后再评估专用时序存储。

系统只按 `siteId + point code` 绑定点位，不接受网关自行指定其他站点。真实点位、单位、量程和状态编码需在平台点位清单中确认。收到数据只代表平台接收成功，不等同于 PLC 设备状态经现场验收。

## 现场联调步骤

1. 按[首站点位映射表模板](首站点位映射表模板.md)核对 PLC、仪表和平台点位，确认读寄存器/数据类型/单位/缩放系数。
2. 为边缘网关配置站点绑定的 ID 与 Token，校准网关时钟，启用 HTTPS 传输。
3. 先用一个低风险只读点位发送数据，检查响应、最近数据时间、来源“现场网关”和数值单位。
4. 扩展到已确认的点位，核对现场表值与平台值；检查点位缺失、超量程和质量状态。
5. 断开云连接，确认 PLC 仍本地运行；恢复后发送缓冲数据，确认历史趋势可查且告警不因重复批次重复触发。
6. 在现场责任人确认后启用对应告警规则，再扩大到其他既有站点。
